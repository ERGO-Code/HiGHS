句柄层：统一所有权边界

owns borrows

ProblemHandle、VectorHandle、WorkspaceHandle 与 CommandBufferHandle 都是只可移动的类型擦除句柄；每个句柄通过 unique_ptr<Resource> owns 一个后端资源。

CUDA graph 的弱生命周期依赖

shared lifetime token weak dependency

每个 CUDA problem/vector/workspace resource owns 一个 shared lifetime token。录制期间，操作把 token 记入依赖集；完成录制时，CommandBufferHandle 保存的是 weak_ptr，因此 graph 不拥有被捕获的数据。

replay 前逐项检查弱依赖；任一资源句柄已经析构，就返回 “command buffer dependency has expired”，而不是访问悬空 Device 地址。

实现： recordDependency / replay

驻留结论

CPU：Problem、16 个向量与两个 workspace scratch 都在 Host；句柄调用不跨总线。

CUDA：这些求解数据常驻 Device；Host 保留 Problem::Data、OriginalModel、HostIterate 与最终 HighsSolution。边界检查优先只下载 compact packet，需要 Host oracle / postsolve 时才下载候选向量。

Setup H2D · Host → Device

bindProblem 上传 costs、bounds、row types、matrix 与 transpose；prepareCheckWorkspace 另上传 scaling、原模型 certificate 与 check 数据。它们在迭代前建立常驻 Device 副本。

Production step：五个有序操作

入口及四次 Backend 调用保持源码顺序。橙色卡片标出恰好两次 SpMV；A * next_primal 不在每个生产步中，它只在边界准备 candidate products 时发生。

  1. enqueueHalpernPdhgStep

    Host 控制器校验 14 个句柄、正步长、迭代计数与 scalar offset，并构造 primal step、dual step、anchor weight。

    CPU lane 同步调用 serial Backend；任一 api::Error 立即返回。
    CUDA lane 向 Backend stream 排队；录制时同样的调用成为 CUDA graph 节点。

  2. fusedProjectedPrimalUpdateAndReflect

    从 current_primal 与 current_aty 计算投影后的 primal_candidate，并产生 reflected_primal = 2*candidate-current。

    CPU lane · column loop serial for col：梯度更新、lower/upper clamp、反射与 finite check。
    CUDA lane · custom kernel projectedPrimalKernel<true>，column-sized grid-stride launch。

  3. multiplyAndProjectedDualUpdateAndReflect

    组合操作先计算 A * reflected_primal → reflected_ax，随后以 row bounds 更新、投影并反射 dual；forward product 不是一个额外的顶层算法调用。

    CPU lane · sparse loop + row loop multiplySparse(matrix, reflected_primal)，再执行 projected dual / reflection loop。
    CUDA lane · vendor + custom executeSpmv → cusparseSpMV，然后 projectedDualKernel<true>。
    SpMV 1/2 · A * reflected_primal

  4. fusedVectorBlend

    用 1/(next_iteration+1) 同时混合 primal/dual anchor 与 reflected vectors，写入 next_primal、next_dual。

    CPU lane · two serial loops 分别遍历 columns 与 rows，检查 weight 和输出有限性。
    CUDA lane · paired kernel 单次 vectorPairBlendKernel 覆盖 max(rows, cols)。

  5. multiplyTranspose，然后 commit state

    计算 A^T * next_dual → current_aty；成功后 swap current/next 指针并增加 iteration。这里没有 A * next_primal。

    CPU lane · transpose sparse loop multiplySparse(transpose, next_dual)；Host 完成 pointer swaps。
    CUDA lane · vendor SpMV executeSpmv → cusparseSpMV；排队成功后 Host 完成 pointer swaps。
    SpMV 2/2 · A^T * next_dual

顺序证据： algorithm/halpern_pdhg_step.cc · backend/cpu/cpu_backend.cc · backend/cuda/cuda_backend.cu

CUDA graph：1 direct + 39 recorded steps

在 40-step cadence 中，RecordedIterationBlock 捕获 39 个 production steps。每步 3 个 scalars，共 39 × 3 = 117 doubles = 936 bytes；replay 前上传参数，随后调用 cudaGraphLaunch。

Replay scheduling：The initial step and the first post-restart step execute directly. Short tails with fewer than 39 remaining steps execute directly.

Time-limit granularity：Host checks the time limit before submitting replay and after it completes; a submitted 39-step block cannot be interrupted by host time-limit checks.

Graph 保留资源的 weak lifetime dependencies，而不是拥有 problem/vector/workspace。捕获、实例化或 replay 的失败保持为 api::Error。

No green failure nodes

Explicit error rail

每一项由命名层创建 structured api::Error，沿调用栈短路到 SolveResult::failure；错误不是成功状态。

  1. Invalid option / argumentAPI translation / algorithm validation → kInvalidOption or kInvalidArgument.
  2. Backend unavailable / not readybackend::createBackend → kBackendUnavailable or kNotReady.
  3. Allocation failureModel, handle or CUDA allocation layer → kAllocationFailure.
  4. Invalid modelmodel::buildProblem / preprocessing → kInvalidModel.
  5. Dimension / alias violationBackend handle validation → structured kInvalidArgument.
  6. Non-finite arithmeticCPU finite checks or CUDA error_flag synchronization → kBackendFailure.
  7. CUDA / cuBLAS / cuSPARSE failureCUDA Backend wrappers → kBackendFailure with operation status.
  8. Graph capture / instantiate / replay failureCUDA Backend command-buffer recorder → kBackendFailure.
  9. Invalid resident checkBackend check / algorithm boundary invariant → kInvalidArgument or kInternal.
  10. Postsolve / original-model KKT failureModel postsolve or independent verifier gate → structured failure; never OPTIMAL.
Selection policy：显式 CUDA 选择直接返回 CUDA 创建错误，不进入 CPU fallback。auto 只应在 CUDA backend creation unavailable 时选择 CPU；当前源码会在 任何 non-OK CUDA 创建错误后选择 CPU，可能吞掉 allocation/backend failures，这是保留的 Review 风险而不是成功语义。

Host fixed cost

Host 预处理与小模型固定成本

症状

小模型端到端时间主要落在模型构建、变换、缩放、norm estimation 与 backend setup，而不是迭代本身。

当前证据

2026-09-08 gate 仍 blocked，且有效分母不完整；现有诊断只能定位阶段，不能推出 release 级结论。

证据路径：docs/hipdlp-phase8-cpu-diagnosis.md

看什么指标

preprocessing_seconds、backend_setup_seconds、operator_norm_seconds 与首步前 wall time。

下一步实验

按模型规模分桶，分别记录冷启动与同进程重复运行，隔离解析、变换、norm 和 backend 创建。

不能破坏

保留 transformation metadata、缩放语义、原模型 postsolve 与 KKT gate；不能把固定成本隐藏在计时窗口外。

CPU scoped comparison

Serial CPU SpMV 与 fused vector loops

症状

每个 PDHG step 有两次 serial SpMV；稀疏访存与逐元素投影/混合循环可能共同限制吞吐。

当前证据

2026-09-14 two-SpMV/CPU fusion 只是工程比较，不是 release acceptance；必须同时报告每步成本和迭代数量，避免把轨迹变化误当作 kernel 加速。

证据路径：docs/hipdlp-phase8-step-fusion.md

看什么指标

step_seconds / recorded_iterations、CPU cycles、cache misses、memory bandwidth，以及 forward/transpose SpMV 占比。

下一步实验

在固定模型、线程、编译选项与停止条件下，用 CPU profiler 对比两次 SpMV 和三个 fused loops。

不能破坏

保持两次 SpMV 的数据依赖、投影边界、finite checks、40-step cadence 和相同终止判定。

CUDA setup

CUDA setup、uploads、descriptors 与 graph capture

症状

短求解可能被 stream/cuBLAS/cuSPARSE 创建、矩阵上传、descriptor、scratch 查询和 graph capture 的一次性成本主导。

当前证据

现有 GPU 报告把 setup 与 steady state 分开，但覆盖范围不足以证明这些固定成本已被所有规模摊薄。

证据路径：docs/hipdlp-phase8-gpu-performance-report.md

看什么指标

backend_setup_seconds、H2D bytes、allocation/descriptor calls、capture/instantiate latency 与首个 replay 前时间。

下一步实验

用 Nsight Systems 比较 cold/warm solve，并按 upload、descriptor、scratch 和 graph construction 标注 ranges。

不能破坏

不能跨维度或已失效资源复用 descriptor/graph；所有 CUDA 创建失败仍必须作为 structured error 暴露。

CUDA scoped replay

Steady-state CUDA SpMV、fused kernels 与 replay

症状

稳定迭代可能受 cuSPARSE SpMV 带宽、custom kernel occupancy、launch gaps 或 graph replay 调度限制。

当前证据

2026-09-22 三案例 fusion-plus-replay 相对 scoped before 下降 41.5%–52.4%；样本很小，不能外推到全部模型。

证据路径：docs/hipdlp-phase8-step-fusion.md；补充：docs/hipdlp-phase8-gpu-performance-report.md

看什么指标

step_seconds、command_buffer_replays、kernel gaps、SpMV duration、achieved bandwidth、occupancy 与 divergence。

下一步实验

先用 Nsight Systems 分离 replay/launch gaps，再按 matrix shape 和 nnz 分桶，用 Nsight Compute 深挖主导 kernel。

不能破坏

保留每步两次 SpMV、39-step recorded block、direct initial/restart/tail steps 与 non-finite error propagation。

Cadence boundary

Cadence boundary、fallback D2H 与 synchronization

症状

正常 112-byte packet 很小，但 resident check、同步或 host oracle fallback 触发完整 candidate D2H 时会形成周期性尖峰。

当前证据

现有 counters 能区分 ordinary boundary 与 fallback；尚需 trace 证明 packet、同步和 candidate download 的实际时间线。

证据路径：docs/hipdlp-phase8-gpu-performance-report.md

看什么指标

boundary_seconds、download_seconds、ordinary D2H bytes/transfers/synchronizations、candidate_downloads 与 host-oracle 次数。

下一步实验

分别采集无 fallback、certificate fallback 与 host oracle fallback，核对每次同步前后的 packet/full-candidate bytes。

不能破坏

不能跳过不确定性 fallback、finite/error_flag 同步、certificate screen 或最终候选下载；失败不能伪装成收敛。

No accepted pair

Scaling、norm guard、PID、restart 与 KKT 轨迹

症状

单步更快仍可能因 operator norm、primal weight、PID 或 restart 改变而增加迭代，甚至在 postsolve/KKT 被拒绝。

当前证据

2026-09-22 large20 screen 的 fully accepted legacy/rewrite pairs 为 0，因此不能建立 speedup 或 release acceptance。

证据路径：docs/hipdlp-phase8-large20-screen.md

看什么指标

recorded_iterations、restarts、weight updates、residual trajectory、status、postsolve 和 original-model KKT。

下一步实验

固定模型、seed、options 与后端，逐项切换 scaling/norm/PID/restart，保存同 cadence 的 residual 与 KKT trace。

不能破坏

只有双方均通过状态、目标值、残差、postsolve 与原模型 KKT 后才能形成性能 pair；不得只比较成功子集。

内存与传输下限估算器

输入变换后问题维度。结果是核心结构的 labeled lower bounds，不是 allocator 或设备峰值承诺。

A + Aᵀ compressed storage 下限
8 column + 8 row vectors 下限
一次 full candidate D2H 下限
正常 CUDA check packet 下限

公式范围：matrix = 两份 values/indices + 两份 row offsets；vectors = 8 * (rows + columns) doubles；candidate = 2 * (rows + columns) doubles；packet = 112 bytes。

下限未计入

  • allocator overhead 与 alignment
  • matrix/vector descriptors
  • cuSPARSE workspaces
  • resident check/certificate duplicates
  • reduction scratch
  • pinned staging buffers
  • graph objects
  • vendor-internal allocations

SolveDiagnostics → profiling 工具地图

先用 solver trace 找阶段和次数，再用相应 profiler 回答“时间在哪里”或“为什么慢”；Compute Sanitizer 用于正确性，不用于证明加速。
