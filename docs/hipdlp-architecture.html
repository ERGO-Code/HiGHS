句柄层：统一所有权边界

owns borrows

ProblemHandle、VectorHandle、WorkspaceHandle 与 CommandBufferHandle 都是只可移动的类型擦除句柄；每个句柄通过 unique_ptr<Resource> owns 一个后端资源。

资源内部的 owner 指针只 borrows 创建它的 Backend，用于拒绝跨后端误用，并不延长 Backend 生命周期。

接口： backend/types.hpp

求解期 Host 缓冲

owns borrows

algorithm::solve owns IterationVectors 的 16 个句柄与 HostIterate 的 primal、dual、ax、aty、reduced_costs。

步进状态只 borrows 这些句柄；候选点下载到 HostIterate 后，postsolve 将变换空间数据恢复为原模型 HighsSolution。

生命周期： algorithm/solver.cc

同一套句柄，两种资源驻留

CPU resource column

CPU / Host
  • CpuProblemResource owns 问题数组、矩阵与转置的 Host 副本。
  • CpuVectorResource owns 一个 std::vector<double>。
  • CpuWorkspaceResource owns row/column scratch，并 borrows check_problem。
  • 下载只是复制 Host vectors；没有 H2D / D2H 边界。

实现： backend/cpu/cpu_backend.cc

CUDA resource column

CUDA / Device
  • CudaProblemResource owns DeviceBuffer 问题数组、CSR/transpose 与 cuSPARSE 描述符。
  • CudaVectorResource owns Device 向量、描述符和可复用 PinnedDownloadBuffer。
  • CudaWorkspaceResource owns Device scratch 与 resident-check / certificate storage。
  • CudaCommandBufferResource owns CUDA graph/executable，但只弱引用其数据依赖。
owns shared lifetime token

CUDA graph 的弱生命周期依赖

shared lifetime token weak dependency

每个 CUDA problem/vector/workspace resource owns 一个 shared lifetime token。录制期间，操作把 token 记入依赖集；完成录制时，CommandBufferHandle 保存的是 weak_ptr，因此 graph 不拥有被捕获的数据。

replay 前逐项检查弱依赖；任一资源句柄已经析构，就返回 “command buffer dependency has expired”，而不是访问悬空 Device 地址。

实现： recordDependency / replay

驻留结论

CPU：Problem、16 个向量与两个 workspace scratch 都在 Host；句柄调用不跨总线。

CUDA：这些求解数据常驻 Device；Host 保留 Problem::Data、OriginalModel、HostIterate 与最终 HighsSolution。边界检查优先只下载 compact packet，需要 Host oracle / postsolve 时才下载候选向量。

传输图例：哪些边界真正搬数据

Setup H2D · Host → Device

bindProblem 上传 costs、bounds、row types、matrix 与 transpose；prepareCheckWorkspace 另上传 scaling、原模型 certificate 与 check 数据。它们在迭代前建立常驻 Device 副本。

Candidate D2H · Device → Host

prepareCandidate 批量下载 primal、dual、candidate_ax、candidate_aty：共 2*(rows+cols) doubles（另有错误标志），供 Host oracle、postsolve 与原空间验证使用。

Resident-check D2H · Device → Host

evaluateCheck 普通边界只下载 compact CheckPacket 并同步；包内 metrics 与 fallback flags 决定是否必须进入完整 Host oracle 路径。

Vector upload H2D · Host → Device

uploadVector 是显式 Host 向量入口；普通零初始化和迭代更新留在 Device kernel 内，不应误记为逐迭代 H2D。

传输证据： CUDA upload / download paths · candidate/check boundary
